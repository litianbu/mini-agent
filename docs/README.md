> 看代码之前先翻 [`s1-code-map.md`](s1-code-map.md)。
> 它把"从浏览器到模型再回来"的路径画成一张图，
> 比按文件名一个个打开高效得多。

## 每份 step 文档的固定结构

```
要解决什么问题 → 核心概念 → 代码地图 → 会踩的坑 → 验收方法 → 下一步
```

## 给第一次进来的读者

1. 先花 5 分钟看 [`00-plan.md`](00-plan.md) 的第二、五节（技术栈 + 路线图），
   知道这套东西为什么这么选、总共要走多远。
2. 再按顺序看 step 文档。**每看完一份，把命令跑一遍** ——
   agent 这种东西，光看代码不会有感觉。
3. 代码里遇到不懂的注释，先看对应 step 文档的"核心概念"那一节。

## 更新规则

- 每完成一步，就补一份 `step-0X.md`，并更新 [`00-plan.md`](00-plan.md) 路线图的状态列。
- 技术选型变了（比如换成 Vue），要回来改 `00-plan.md` 的第二节，
  **并写清楚为什么换** —— 决策的理由比结论值钱。
